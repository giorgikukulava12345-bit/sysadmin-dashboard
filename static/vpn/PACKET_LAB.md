# Free local vision AI and reviewed Packet Tracer lab workspace

## Local AI (optional, no paid API)

The workspace supports image-and-task reasoning through a locally installed Ollama Qwen3-VL **Instruct** model. The CPU default is `qwen3-vl:2b-instruct` (1.9 GB); larger choices are `qwen3-vl:4b-instruct` (3.3 GB) and `qwen3-vl:8b-instruct`. Bare size aliases, thinking variants and cloud model IDs are not accepted: upstream aliases can change, and a thinking variant caused CPU-only requests to exceed the timeout during testing. Start Ollama, pull the desired explicit model and run `static/agent/noc_lab_ai.py` with Python 3.10+. The Windows `start_lab_ai.ps1` launcher checks prerequisites, verifies the helper checksum, pulls the selected local model, and starts the helper. It does not change global execution policy, open network interfaces or install a startup service.

The helper binds **127.0.0.1:8767 only**, forwards to **127.0.0.1:11434 only** without proxies, requires the exact production website Origin/loopback Host and a random per-process bearer token, and handles browser local-network preflight. No image/task/token logging, shell execution, device access, arbitrary endpoint, cloud model or model pull endpoint is exposed. One bounded inference runs at a time; request/image/output sizes and timeouts are limited.

`packet-lab-ai.js` uses a fixed localhost helper URL, creates whole-page and detail views, sends them and a compact task/service catalog to the local helper and validates the draft atomically. The model schema bounds devices, services, text and output tokens and forbids arbitrary device/service fields. Unknown devices/services/types are rejected. Missing service fields become empty values rather than unrelated lab defaults. Unknown router hardware requires explicit user selection before CLI export. Layer 2 hosts may leave a gateway blank when none is specified. The imported draft stays editable, cannot auto-generate/apply CLI, displays uncertainties and requires a fresh review checkbox. Previous forms can be restored; stale results are ignored. Clear removes the token and draft.

Vision AI can misread small labels, infer a wrong link or misunderstand incomplete lab sheets. Original screenshots are required for readable detail. Destructive cleanup stages and unsupported/missing requirements must be reported as uncertainties, not invented commands. This is not a guarantee of universal or error-free Packet Tracer support. Local CPU inference can take minutes; cancellation stops importing the result, while the local model may finish computing its current request.

Tests: `node tests/packet-lab-ai.test.js`, `python -m unittest discover -s tests -p test_lab_ai.py` (5 tests), and `tests/packet-lab-ai.html` (17 UI assertions). Actual vision inference and production connection are verified separately from mocked UI transport.

`packet-lab-ui.js` mounts a separate collapsed workspace before the lab. It does not restore the removed current-configuration analyzer or switch/host tabs in the existing router workbench.

Workflow: upload/paste an image, enter the full assignment, then either use local vision AI to propose device/service forms or use enhanced OCR and manually complete them. Confirm review before generating. Every device gets separate plain-text configuration/instructions, copy/download and EXEC verification commands. Changing an input removes old results. Clear removes lab data and the AI session token. Nothing is saved to browser storage or posted to the website server; local AI sends image/task data to the user's own loopback helper.

OCR is Tesseract.js 7 with the existing pinned multi-pass recognition pipeline. Engine/language files download from jsDelivr; images remain in the tab. English OCR is used. This is **not a vision language model**: arbitrary prose, wire crossings, missing labels, Georgian OCR, and assignment intent are not automatically solved. Device-name suggestions never assign ports or IPs. Use original-resolution screenshots and manually verify every digit. No promise of error-free recognition or universal Packet Tracer CLI coverage is made.

Supported model port maps: 2911, 1941, 2811; Layer 2 2960; Layer 3 3560; PC/host manual Desktop setup. Serial ports require explicit installed-module confirmation. Routed IPv4, VLAN SVI and tagged subinterface addressing are supported; service forms reuse existing validators for switching, OSPF/EIGRP/BGP, IPv6 static/OSPFv3, ACL/NAT/DHCP, FHRP, SSH, NTP/SNMP and other listed templates. Added local forms cover IPv6 addressing, RIPv2, native VLAN trunks, console local login, syslog and serial HDLC/PPP/Frame Relay.

Reciprocal IPsec router entries use the existing validated Packet Tracer IKEv1 lab suite. Both peers and PSKs must match. IKEv2 is not offered for Packet Tracer. The combined NAT/firewall + IPsec case is deliberately blocked here and remains in Quick Setup + VPN, which owns NAT exemptions. No encryption downgrade is inferred from an image.

One malformed device blocks the entire lab export. Duplicate IPv4 addresses/hostnames, model port mismatches, missing interface references and incomplete VPN peers are blocked. The user must verify links, VLAN continuity, protocol adjacencies, existing configuration, image capabilities and task coverage. This workspace targets a clean lab; it does not merge running configurations or apply/save anything to devices.

Tests: `node tests/packet-lab.test.js`; browser fixture `tests/packet-lab.html`. Verification performed with local upload → real OCR → three-device review → generation → copy → input invalidation. Synthetic screenshot labels included an ambiguous switch caption, demonstrating why confirmation is required.
